# 做成 · 美食执行助手 v0.1

这是第一版个人移动端原型，目标是跑通“收藏 → 结构化 → 推荐 → 做菜 → 记录成品”的闭环。

## 运行

在项目目录启动静态服务器：

```powershell
python -m http.server 4311 --directory designs
```

打开：<http://localhost:4311/food-flow/index.html>

也可以直接用浏览器打开 `index.html`，但使用 HTTP 服务时，PWA manifest 和多端预览更稳定。

## 抖音解析接口（v0.7）

前端会优先请求 `/api/douyin/parse`。本地可启动接口：

```powershell
node server/douyin-api.mjs
```

默认监听 `http://localhost:4320`。如果前端和接口不是同一个地址，可在浏览器控制台设置：

```js
window.FOODFLOW_API_URL = 'http://localhost:4320/api/douyin/parse'
```

接口默认只负责校验来源并返回“待人工确认”，不会绕过抖音登录或反爬限制。配置经过授权的解析供应商后，可通过 `DOUYIN_PROVIDER_URL` 和 `DOUYIN_PROVIDER_TOKEN` 转发请求。

## 第一版包含

- 菜谱库、搜索与筛选
- 复制链接生成可校对的菜谱草稿
- 成品预期描述与实际制作记录
- 家庭库存与按食材匹配推荐
- 减脂标签与解释
- 分步骤烹饪模式、计时器
- 成品照片、评分和经验备注
- 浏览器本地数据持久化

## 当前边界

- 当前支持抖音短链、完整链接和分享口令的前端识别，并保留文字 / 截图兜底；尚未接入需要登录或服务端代理的真实视频内容解析。
- 未配置解析供应商时，产品只生成“本地模板”，不会把猜测标记为 AI 识别结果。
- 数据保存在当前浏览器的 localStorage 中，尚未接入账号与云端同步。
- 示例菜品使用本地生成的成品摄影图；抖音原视频封面仍需通过后端解析或用户截图补充。
